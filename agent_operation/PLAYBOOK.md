# Operation Playbook

## Phase 0: Instrumentation and Readiness

集客開始前に次を確認します。

- ストアから初回Hangout成立までチャネルを保持して計測できる
- `area_bucket`、`time_window`、`activity_category` で匿名集計できる
- 正確な緯度経度を分析基盤や広告基盤へ送らない
- 参加承認前は正確な集合位置を表示しない
- 通報、ブロック、キャンセル、無断欠席の運用がある
- 空状態から募集作成へ進める
- Hangout共有リンクが活動、開始時刻、概略エリア、残席を表示する

## Phase 1: Seed One Cell

最初のセル例は `新宿 x 金土 18:00-22:00 x カフェ・食事` です。実データから別のセルを選んでも構いません。

1. 初期ホスト候補を集める
2. 実在する募集を対象時間帯へ集中させる
3. 公式主催は公式と明示する
4. クローズドテストで申請、承認、チャット、集合、フィードバックを完走する
5. 安全上の問題と離脱箇所を修正する

## Phase 2: Controlled Launch

- 対象セルだけに短尺動画、提携QR、共有リンクを出す
- クリエイティブと遷移先を同じ活動テーマにする
- 初週は運営担当者が問い合わせと通報に対応できる時間だけ送客する
- 毎日、供給、申請、承認、3H Match、安全指標を確認する
- 空一覧または安全悪化が発生したセルへの送客を止める

## Phase 3: Retention Loop

Hangout終了後に次の行動を1つだけ提示します。

- 参加者: 次回候補を保存または友人を1人招待
- ホスト: 前回内容から再募集
- 未成立ユーザー: 同じ時間帯の近い代替募集へ案内

報酬を使う場合、ダウンロードではなく「安全に完了した初回Hangout」を条件にします。自己紹介、複数アカウント、偽参加への対策を同時に設計します。

## Phase 4: Expand

拡大単位は1都市ではなく、隣接する1セルです。

1. 隣接エリアまたは新しい時間帯を1つ選ぶ
2. 先にホストと募集を確保する
3. 小規模に送客する
4. 成立率、安全性、継続率を既存セルと比較する
5. 基準を満たした場合だけ継続する

## Weekly Operating Cycle

### Monday

- 前週ファネルと安全指標を確認
- 最大のボトルネックを1つ選ぶ
- 実験を最大3件に絞る

### Tuesday to Thursday

- 承認済み施策を実施
- 計測欠損、空一覧、安全兆候を監視
- 停止条件に達した施策を止める

### Friday to Sunday

- 重点時間帯の供給と運営対応を厚くする
- 数値だけでなく、同意を得たユーザーフィードバックを確認

### Next Monday

- `WEEKLY_REPORT.md` 形式で結果をまとめる
- `keep / change / stop` を決定する
- 学びを次の1実験へ反映する
