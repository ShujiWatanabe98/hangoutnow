# Hangout Now 集客・運用プレイブック

最終更新: 2026-08-20

## 目的

アクセス数だけを増やすのではなく、次の利用行動につながる対象者を `https://method-more.com/` へ案内します。

`流入 → Hangout一覧 → 詳細確認 → 登録 → 参加申請または主催 → 承認 → 実参加`

最重要指標は「週に完了したHangout数」と「登録後7日以内に参加申請または主催した割合」です。

## 最初の対象者

1. 東京在住の23〜34歳の社会人。仕事帰りや休日に30〜120分の空き時間があり、食事、カフェ、ランニング、散歩などへ一人で参加したい人
2. 上京、転勤、進学後に、恋愛相手を先に選ぶのではなく共通の趣味から友達を探したい22〜39歳の人
3. カフェ、ランニング、語学交流など、少人数の活動を安全に主催したい25〜45歳の人

初期エリアとテーマは「渋谷 × カフェ」「新宿 × 食事・飲み」「東京 × ランニング」「今から × 近く」に集中します。実際に参加できるHangoutが不足している時間帯には広告で流入だけを増やしません。

## 伝える価値

- 誰と会うかより先に、何をするかを決める
- 今夜、近く、30〜90分の短い活動から始められる
- 一人参加しやすい少人数の活動を選べる
- 主催者が参加申請を確認して承認する
- 正確な集合場所は承認後だけ共有する
- AIは成立を保証せず、興味に合いそうな活動を探す補助として使う

## UTM命名規則

外部からのリンクだけにUTMを付け、サイト内リンクには付けません。値は小文字の英数字とハイフンに統一し、氏名、メール、電話番号、ユーザーID、正確な位置を入れません。

| 項目 | 例 |
|---|---|
| `utm_source` | `instagram`, `x`, `line`, `newsletter`, `partner-coworking-a` |
| `utm_medium` | `organic-social`, `email`, `referral`, `qr`, `paid-social` |
| `utm_campaign` | `tokyo-launch-202609` |
| `utm_content` | `reel-cafe-01`, `post-safety-02`, `story-running-01` |
| `utm_id` | `tokyo-launch-202609` |
| `utm_source_platform` | `instagram`, `x`, `line` |

例:

```text
https://method-more.com/shibuya-cafe-friends.html?utm_source=instagram&utm_medium=organic-social&utm_campaign=tokyo-launch-202609&utm_content=reel-cafe-01&utm_id=tokyo-launch-202609&utm_source_platform=instagram
```

投稿前に、投稿日、担当者、対象者、投稿先、リンク、全UTM、素材名、安全確認担当、結果、継続または停止判断を台帳へ記録します。短縮URLは使わず、`method-more.com` の完全なURLを掲載します。

## 計測イベント

GA4はCookie同意済みの訪問だけを計測し、自社DBの利用集計とは分けます。個人名、メール、電話番号、正確な位置、トーク内容、Hangoutタイトルを送信しません。

| 段階 | イベント | 用途 |
|---|---|---|
| 興味 | `cta_click` | CTA名、位置、ページ種別を比較 |
| ガイド | `guide_open` | 対象別ガイドへの遷移を比較 |
| デモ | `demo_open` | デモ開始を計測 |
| 見込み | `generate_lead` | ニュースレター登録成功を計測 |
| 共有 | `share` | 共有方法と対象ページを計測 |

次の実装段階で、登録成功、Hangout詳細、参加申請、主催、承認、完了を同じ流入単位で安全に接続します。マッチング学習用の同意付き行動ログを、マーケティング母数の代わりには使いません。

## 週次運用

- 月曜: GA4、Search Console、自社DBを確認し、前週の流入から実参加までを集計。改善仮説を1件に絞る
- 火曜: 検索語、問い合わせ、SNS反応から企画を3件作る。実在する活動と場所を確認する
- 水曜: 実用ガイド1本、短尺動画1本、X投稿1〜2本を準備する
- 木曜: カフェ、コワーキング、ランニングクラブなどへ協力候補を整理する
- 金曜: 週末の実在する活動、新着情報を案内し、登録とCTAを実機確認する
- 土日: コメント、主催者、参加者を支援し、虚偽の残席や開催できない募集を案内しない

毎日、本番トップ、重点ガイド、登録、APIヘルス、Search Consoleの「セキュリティの問題」「手動による対策」を確認します。

## 最初の30日

1. 1週目: CTA・UTM・計測を整え、重点エリアの供給状況と登録経路を確認
2. 2週目: 渋谷カフェ、新宿食事の情報発信と、主催者候補5〜10人の確保
3. 3週目: 東京ランニング、「今から」の情報発信と、地域パートナー候補3件への提案準備
4. 4週目: 成立・実参加まで到達した流入元だけを継続し、アクセスのみの施策を停止

最初の2週間は基準値を集め、その後はホームからアプリまたはデモへのCTR 20%以上、登録後7日以内の参加申請または主催15%以上、承認後の完了70%以上を暫定目標にします。

## 公開前の確認

- 対象者と目的が1つに絞られている
- リンク先が本番でHTTP 200になり、スマートフォンでCTAを操作できる
- 日時、残席、利用可能な機能、体験談が事実である
- デモ人物を実在利用者のように見せない
- AIが成立を保証する表現を使わない
- 正確な集合場所、私信、氏名、顔写真を無断公開しない
- 写真、音楽、文章の権利を確認する
- 提供または依頼した投稿は広告であることを明示する
- UTMを台帳と照合する

Googleのセキュリティ警告、重大な登録障害、個人情報や正確な位置の露出、重大な安全報告、虚偽表示、権利侵害が起きた場合は流入施策を停止し、原因と復旧条件を記録してから再開します。
