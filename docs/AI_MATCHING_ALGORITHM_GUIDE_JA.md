# Hangout Now AIマッチングアルゴリズム解説書

最終更新: 2026-08-19  
対象実装: `match-v1.2.0` および管理画面で有効化された後続バージョン

## 1. 目的

Hangout Nowの基本思想は、**「人を先に選ばず、活動を先に選ぶ」**ことです。マッチングエンジンは、ユーザー同士を直接順位付けするのではなく、ユーザーごとに「どのHangoutが今の希望に合うか」を計算し、発見画面の表示順を最適化します。

現在の実装は、生成AIやブラックボックス型の機械学習モデルではありません。運営者が説明・監査・調整できる**重み付きルールベース・レコメンドエンジン**です。本書では、便宜上これを「AIマッチング」と呼びます。

`match-v1.2.0` は、活動意図、生活リズム、身体・時間リズム、意思決定傾向、移動・場所、参加ペース、活動スタイル、信頼・安全の8パターンを別々に集計します。過去行動よりも、その時点で明示された「やりたい活動」を優先します。

## 2. 処理の全体像

```text
ユーザーの明示設定
  + 同意済みの利用傾向
  + Hangoutの活動・時間・エリア・主催者情報
  + 主催者の信頼・安全シグナル
                    ↓
            重み付きスコア計算
                    ↓
              40〜99に丸める
                    ↓
       スコア降順 → 時刻または距離順
                    ↓
             発見画面へ表示
```

マッチングデータ利用へ同意していない場合は個別計算を行わず、スコアを一律 `70` とします。

## 3. 使用するデータ

### 3.1 ユーザーが明示的に設定する条件

- 希望エリア
- 希望する活動
- 希望年齢の下限・上限
- 希望する性別
- 曜日と時間帯
- 参加したい時期（今すぐ、今日、今週、週末、柔軟）
- 移動できる時間
- 希望人数
- 予算の下限・上限
- 交流スタイル
- 参加目的
- 初参加時の希望
- 飲酒・喫煙の希望
- 避けたい条件
- 日程の柔軟性
- 希望言語（日本語、英語、韓国語、中国語）
- マッチングデータ利用への同意
- 行動学習の有効・無効

このうち、現行のスコア計算へ直接使われるのは、活動、エリア、年齢、性別、曜日・時間帯、参加時期、人数、交流スタイル、言語です。移動時間、予算、参加目的、初参加条件、飲酒・喫煙、避けたい条件、柔軟性は保存済みですが、現行バージョンではまだ直接の加減点に使われていません。

### 3.2 Hangout側の情報

- カテゴリ
- タイトル
- サービスエリア
- 承認前に公開する概略エリア
- 開始日時
- 最大参加人数
- 主催者の年齢、性別、交流スタイル、言語

### 3.3 同意済みの行動シグナル

行動学習が有効な場合に限り、直近データから活動カテゴリとエリアの傾向を加点します。

| 行動 | 1件あたりの基本強度 |
|---|---:|
| 詳細閲覧 | `+0.25` |
| ハート | `+0.8` |
| 自分で主催 | `+1.2` |
| 承認されて参加 | `+1.5` |

各行動種別は最大50件を取得し、計算へは新しい順に最大12件を利用します。同じカテゴリなら強度をそのまま、同じエリアなら強度の45%を基礎値とします。さらに30日で影響が半分になる時間減衰を適用し、意思決定傾向の加点は合計`+8`を上限にします。

### 3.4 主催者の信頼・安全シグナル

- 評価件数に応じて信頼度補正した平均評価
- 主催したHangoutの開催完了率
- 主催Hangoutのグループトーク参加率
- 運営による警告、一時停止、永久停止の件数

トークについては本文を解析せず、主催者がグループトークへ参加したかという集計だけを使います。警告などの運営措置は安全性ペナルティとして減点します。

## 4. スコア計算

標準設定では基準点を `62` とし、条件ごとに加点・減点します。

| 判定項目 | 一致 | 不一致 |
|---|---:|---:|
| 活動 | `+12` | `-4` |
| エリア | `+10` | `-5` |
| 曜日・時間帯 | `+8` | `-3` |
| 希望人数 | 完全一致 `+7` | 2人以内の差 `+2.8`、それ以外 `-3` |
| 主催者の年齢 | `+5` | `-5` |
| 主催者の性別 | `+4` | `-4` |
| 交流スタイル | `+3` | 加減点なし |
| 言語 | `+4` | 最大 `-2` |

活動はカテゴリ、タイトル、カテゴリ別の日本語別名を緩やかに照合します。例えば `CAFE` は「カフェ」「コーヒー」、`RUNNING` は「ランニング」「運動」「スポーツ」も検索対象です。

### 4.1 参加時期

| 希望 | 一致条件 | 加点 | 不一致 |
|---|---|---:|---:|
| 今すぐ | 開始まで3時間以内 | `+7` | `-3` |
| 今日 | 開始まで24時間以内 | `+5` | `-2` |
| 今週 | 開始まで7日以内 | `+4` | `-2` |
| 週末 | 土曜日または日曜日 | `+5` | `-2` |

### 4.2 評価・完了・会話

- 平均評価は3点を中心に、最大 `-4〜+4`
- 開催完了率は70%を中心に、最大 `-3〜+3`
- グループトーク参加率は最大 `+2`
- 安全措置は1件につき標準 `-4`、最大 `-8`

### 4.3 最終値

```text
rawScore = 基準点
         + 明示条件の一致・不一致
         + 参加時期
         + 同意済み行動傾向
         + 主催者の信頼・安全シグナル

matchScore = round(rawScore) を 40〜99 の範囲へ制限
```

画面では `matchScore` をパーセント形式で表示します。これは統計的な成立確率ではなく、現行ルールに基づく**相対的な相性スコア**です。

## 5. 表示順位

1. マッチングスコアの高い順
2. 同点の場合:
   - 現在地がない場合は開始日時が早い順
   - 現在地がある場合は距離が近い順

ブロック関係の相手は候補から除外されます。通常ユーザーには公開デモ用Hangoutを表示しません。正確な集合場所と座標は参加承認後だけ表示します。

## 6. 同意・プライバシー・安全

- マッチングデータ利用へ同意しない場合は個別最適化しません。
- 行動学習は別の設定で無効化できます。
- 正確なGPS座標をマッチングプロフィールとして保存しません。
- 承認前は概略エリアだけを利用・表示します。
- パスワード、トーク本文、プッシュトークンをマッチング材料にしません。
- トークの「内容」から人格や社会適合性を自動判定しません。
- 安全性は運営が確定した措置の件数を限定的に利用します。
- スコアはユーザーの人格・価値を表すものではありません。

## 7. 管理画面

運営管理画面では以下を確認できます。

- 有効なアルゴリズムバージョン
- 登録ユーザー数
- 24時間、7日、30日のアクティブユーザー数
- Hangout数、開催完了数、平均評価、評価件数、通報数
- 詳細閲覧 → 参加申請 → 承認 → 開催完了のファネル
- 評価分布
- マッチング不成立理由
- バージョン別の成立・不成立フィードバック
- 各重みの棒グラフ
- 重み変更時の推定高一致スコア
- 設定の下書き、有効化、変更履歴

管理者は直接本番値を上書きせず、次の手順で変更します。

```text
新バージョン番号と変更理由を入力
  → 下書きを保存
  → 内容を確認
  → 有効化
  → 旧バージョンを自動的にアーカイブ
```

コード内の標準値は `match-v1.2.0` です。DBに有効な設定がある場合は、そのバージョンと重みを優先します。

## 8. 効果検証

次の指標をバージョン単位で比較します。

- 詳細閲覧率
- 参加申請率
- 承認率
- 開催完了率
- マッチング成立・不成立
- 不成立理由
- 評価平均と分布
- キャンセル率
- 通報・安全措置率

現在は、AI検証専用の架空5アカウントと、成立2件・募集中1件のHangout、閲覧・ハート・申請・承認・トーク・完了・評価・不成立理由の履歴を本番検証環境へ投入しています。

## 9. 現行版の限界

1. 「94%」などの値は実際の成立確率へ統計校正されていません。
2. 予算、移動時間、飲酒・喫煙など、保存済みでも未使用の項目があります。
3. 活動名の照合は文字列と固定別名が中心です。
4. 季節、天候、交通、空席などの外部状況は未使用です。
5. 新規ユーザー・新規主催者は行動履歴が少なく、明示設定へ依存します。
6. 行動履歴には時間減衰と加点上限がありますが、減衰期間の統計的な最適化は今後必要です。
7. 公平性指標とグループ別の偏り監査は、運用ルールとして今後追加が必要です。

## 10. 今後の発展

### 段階1: 現行ルールの改善

- 保存済みの予算・移動時間・飲酒・喫煙条件を計算へ追加
- 行動履歴の減衰期間と上限を検証データで調整
- 不成立理由から項目別重みを調整
- スコア内訳を管理者だけが確認できる説明画面を追加

### 段階2: 統計モデル

- 参加申請、承認、開催完了を目的変数にする
- 学習用・検証用・期間外テストへ分割する
- ルール版と統計版をオフラインで比較する
- 成立率だけでなく安全性、満足度、キャンセル率も最適化する

### 段階3: 本番実験

- バージョンごとの段階的ロールアウト
- A/Bテスト
- 公平性・安全性・地域偏りの監視
- 問題発生時に即時ロールバック

機械学習を導入しても、安全条件、ブロック、位置情報の公開範囲、年齢・参加条件などのハードルールはモデルより優先します。
