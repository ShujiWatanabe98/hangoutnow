# First 100 Users Strategy

**作成日:** 2026-08-13  
**対象:** Hangout Now初期公開  
**目的:** 同じ場所・時間帯へ集中した100人にダウンロードしてもらい、安全な初回利用と継続利用につなげる。

## Executive decision

初期100人は、全国の無関係な100ダウンロードではなく、次の1セルで活動できる100人とします。

> 新宿駅周辺約2km × 金曜・土曜18:00–22:00 × カフェ・早めの食事 × 18歳以上

100人の構成目標:

- 初期ホスト: 20人
- 参加中心ユーザー: 60人
- 予備ホスト兼参加者: 20人

登録順に一斉開放せず、25人ずつ4コホートに分けて招待します。各コホートで供給、安全性、成立率を確認してから次を開放します。

## What success means

### Acquisition target

- Verified downloads: 100
- Registration completed: 80以上
- Phone verification completed: 60以上

### Usage target

- Activation: 50人以上
  - 登録後24時間以内の参加申請または募集作成
- Hangout creators: 20人以上
- Join request users: 40人以上
- 3H matched Hangouts: 30件以上
- Attendance confirmations: 40人以上
- D7 active users: 25人以上

### Satisfaction and safety guardrails

- 開催後満足度: 平均4.0/5以上、回答率50%以上
- 「同じ条件なら再利用したい」: 70%以上
- 重大安全インシデント: 0
- 承認前の正確な位置情報露出: 0
- 通報への初動: テスト運用時間内30分以内
- 無断欠席率: 15%未満を初期仮説とし、実データで更新

これらは実績ではなく初期判断基準です。

## Four-cohort launch

### Cohort 0 — Internal journey test: 10 people

**Purpose:** ストア公開前または限定配布で、主要導線と運用手順を確認する。

- ホスト4人、参加者6人
- 実在する募集4件
- 2アカウント間の登録、申請、承認、座標解禁、チャット、完了、評価
- 通報・ブロックの模擬訓練
- 全参加者から15分の観察・フィードバック

**Gate:** P0/P1不具合0、位置情報漏えい0、サポート手順が機能。

### Cohort 1 — Founding hosts: 25 people

**Purpose:** 参加者獲得前に供給を作る。

- ホスト10人以上
- 金土それぞれ6〜8件の募集を事前設定
- 各ホストが活動内容を伝えて成人1〜2人を招待
- 公式募集は運営主催と明記

**Gate:** 重点時間帯のSupply Coverage 70%以上、3H Match Rate 30%以上、重大安全問題0。

### Cohort 2 — Controlled community launch: cumulative 50 people

**Purpose:** 新宿へ来る既存コミュニティの成人を追加する。

- コワーキング、社会人サークル、ランニング・カフェ系コミュニティなどへ個別提案
- QRは施設全体へ無差別掲示せず、対象日時の案内とセットにする
- 招待先には、その週に参加可能なHangoutを必ず表示

**Gate:** Activation 45%以上、3H Match Rate 35%以上、満足度4.0以上。

### Cohort 3 — Creator and referral launch: cumulative 75 people

**Purpose:** 検証済み利用場面を短尺動画で伝える。

- 新宿、一人行動、カフェ、社会人生活に特化した小規模発信者2〜3人
- 同意済みの出演者だけを利用
- 動画ごとに専用リンクを使用
- 「知らない人と会う」より「今から同じ活動」を中心にする

**Gate:** 流入元別Activation 40%以上。低品質流入は停止。

### Cohort 4 — Complete the first 100

**Purpose:** 最も質の高かったチャネルだけで残り25人を獲得する。

- 参加者からの1対1招待
- 成立率が高かったコミュニティを再利用
- 必要なら小額広告を上限付きで実施
- 100人到達後は新規獲得を一時抑え、D7と供給を確認

**Gate:** 100ダウンロードに加え、Activation 50人以上と安全基準達成。

## Core message

### Primary

> 今から何する？ 活動からつながる、近くのHangout。

### Supporting message

> 30分後・1時間後・3時間後。カフェや食事など、やりたいことを選んで参加申請。

### Trust message

> 18歳以上限定。電話番号確認。承認前は概略エリアだけを表示し、承認後に集合場所を共有。

### Prohibited messages

- 必ず会える、絶対安全、友達ができるなどの成果保証
- 孤独や不安をあおる表現
- 恋愛・性的出会いを暗示する表現
- 実績のない「人気」「多数利用」「満足度」
- 架空レビュー、架空参加者、架空募集

## Store conversion plan

最初のスクリーンショット3枚:

1. 「今から何する？」— 活動と開始時刻を選ぶ画面
2. 「活動から参加申請」— 人物より活動を先に見せる
3. 「承認後だけ集合場所を共有」— 電話確認、通報、ブロックを含む

公開前にiOSの予約注文、Google Playの事前登録が利用可能なら、待機リストから直接誘導します。公開後に十分な閲覧数が得られた段階で、Apple Product Page Optimizationを使い、アイコンまたは最初のスクリーンショットを1変数ずつ比較します。

活動別のカスタムストアページは、初期100人ではデータが分散しすぎるため、標準ページを優先します。コミュニティ専用リンクでは流入元だけを保持し、正確な位置情報を含めません。

## Content plan

公開前に次の短尺素材を6本用意します。

1. 予定が空いた→1時間後のカフェを探す
2. 人ではなく「何をするか」から選ぶ
3. 参加申請→主催者承認→集合場所表示
4. 初めて参加するときの安全ルール
5. 30秒で募集を作る
6. 公共の場所で短時間Hangout

実在ユーザーを撮影する場合は用途、媒体、期間の同意を得ます。チャット、正確な場所、通知、第三者の顔を映しません。

## Host program

### Host requirements

- 18歳以上、電話確認、プロフィール写真
- 公共の場所を指定
- 申請へ原則30分以内に回答
- 営業、勧誘、恋愛・性的目的を禁止
- キャンセル時は速やかに通知

### Host support

- 15分の合同オンボーディング
- 募集文テンプレート3種
- 初参加歓迎ラベル
- 申請・開始前リマインダー
- 緊急・通常の問い合わせ先を分離

報酬を使う場合は架空の募集数やレビューではなく、実際に安全運営したテスト協力への定額補助とします。

## Weekly execution

### T-4 to T-3 weeks

- モバイル主導線、安全機能、計測の公開条件を満たす
- 成人20人のインタビューを実施
- 初期ホスト10人を確保
- ストア素材と公開ページを作成

### T-2 weeks

- Cohort 0を実施
- 不具合修正と運用訓練
- ホスト募集を20人へ拡大
- 金土の募集カレンダーを確定

### T-1 week

- Cohort 1を招待
- 予約注文・事前登録または待機リストを案内
- コミュニティ2〜3件と公開日を調整
- Go / No-Goレビュー

### Launch week

- Cohort 2、3を順番に開放
- 金土18〜22時に運営待機
- 日次でSupply、Activation、3H Match、安全、満足度を確認
- 空一覧や安全悪化があれば次コホートを停止

### Week 2

- 成績のよいチャネルだけでCohort 4を追加
- 100ダウンロード後、D7確認まで獲得を抑制
- keep / change / stopを3エージェントで決定

## Instrumentation required before launch

- install source / campaign
- registration completed
- phone verification completed
- discover viewed
- Hangout created
- join requested / accepted
- matched within 3 hours
- attendance confirmed
- feedback submitted
- retained action
- report / block / cancellation / no-show aggregate

正確なGPS、メール、電話、チャット本文、自由記述をマーケティングイベントへ含めません。

## Stop conditions

次のいずれかで新規招待を止めます。

- 重大安全インシデント
- 正確な位置情報の承認前露出
- 通報・ブロックが機能しない
- 重点時間帯のSupply Coverageが50%未満
- 運営対応可能人数を超える
- P0/P1障害
- 1コホートで満足度3.5未満

## Agent responsibilities

### agent_marketing

- 成人インタビュー、チャネル候補、メッセージ検証
- 100人の候補パイプラインと流入元管理
- ストア素材、短尺動画、紹介文の作成
- Qualified Downloads、Activation、D7の評価

### agent_operation

- ホスト20人、募集カレンダー、運営当番の確保
- 問い合わせ、通報、無断欠席、キャンセル対応
- 費用上限とCost per Activated Userの監視
- 各コホートのGo / Pause提案

### agent_development

- 公開条件となるモバイル導線、安全、出欠・評価、計測の実装
- ストアリンク、共有リンク、アトリビューション
- 障害、安全境界、性能の検証
- MarketingとOperationへ実装可否と結果を返す

## Human approvals

- 各コホートのGo / No-Go
